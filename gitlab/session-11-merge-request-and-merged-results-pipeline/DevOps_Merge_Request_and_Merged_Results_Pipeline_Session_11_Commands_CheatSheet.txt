Options:
- `-l` = `--list`: Lists packages known to `dpkg`.

- `-E` = `--extended-regexp`: Makes `grep` interpret the pattern as an extended regular expression.
- `'^ii\s+gitlab-(ce|ee)\s'` = regular-expression argument: Matches installed package lines for either `gitlab-ce` or `gitlab-ee`.

# cat > validate_config.py <<'PYTHON'
from app import DEFAULT_PORT

with open("deployment.conf", encoding="utf-8") as file:
    line = file.read().strip()

key, value = line.split("=", 1)

if key != "PORT":
    raise SystemExit("FAIL: deployment.conf must contain PORT")

deploy_port = int(value)

if deploy_port != DEFAULT_PORT:
    raise SystemExit(
        f"FAIL: deployment PORT={deploy_port} "
        f"but application DEFAULT_PORT={DEFAULT_PORT}"
    )

print(
    f"PASS: deployment PORT={deploy_port} "
    f"matches application DEFAULT_PORT={DEFAULT_PORT}"
)
PYTHON

Explanation:
Writes the complete Python validation script into `validate_config.py`. The quoted here-document prevents the shell from expanding anything inside the Python code.

Options:
- `>` = output redirection: Creates `validate_config.py` if needed and replaces its existing contents.
- `<<'PYTHON'` = quoted here-document: Passes the Python code literally to `cat` until the closing `PYTHON`.

# git fetch origin "${CI_MERGE_REQUEST_TARGET_BRANCH_NAME}:refs/remotes/origin/${CI_MERGE_REQUEST_TARGET_BRANCH_NAME}"

Explanation:
Fetches the merge request target branch from `origin` and writes it to the matching remote-tracking reference under `refs/remotes/origin/`.

Options:
- `${CI_MERGE_REQUEST_TARGET_BRANCH_NAME}:refs/remotes/origin/${CI_MERGE_REQUEST_TARGET_BRANCH_NAME}` = Git refspec: The left side is the remote source branch and the right side is the local destination reference.
------------------------------------------------------------

------------------------------------------------------------
# git checkout -B ci-merged-result "$CI_COMMIT_SHA"

Explanation:
Creates or resets `ci-merged-result` at `CI_COMMIT_SHA` and checks that branch out.

Options:
- `-B` = create or reset branch: Creates `ci-merged-result` if it does not exist, or resets it to the specified start point if it already exists.
- `$CI_COMMIT_SHA` = shell variable expansion: Supplies the current CI commit SHA as the branch start point.
------------------------------------------------------------

------------------------------------------------------------
# git merge --no-commit --no-ff "refs/remotes/origin/${CI_MERGE_REQUEST_TARGET_BRANCH_NAME}"

Explanation:
Merges the fetched target branch into the current branch but stops before creating a merge commit. It also prevents Git from using a fast-forward-only update.

Options:
- `--no-commit` = do not automatically create the merge commit: Stops before committing a successful non-fast-forward merge.
- `--no-ff` = no fast-forward: Forces merge-style integration instead of moving the branch pointer with a fast-forward.
- `${CI_MERGE_REQUEST_TARGET_BRANCH_NAME}` = shell variable expansion: Inserts the merge request target branch name into the remote-tracking reference.
