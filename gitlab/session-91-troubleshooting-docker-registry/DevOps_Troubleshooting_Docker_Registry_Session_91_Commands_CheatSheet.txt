------------------------------------------------------------
# docker version

Explanation:
Shows Docker client and server version information so you can confirm that the CLI can communicate with the Docker daemon.
------------------------------------------------------------
# docker build -t "$IMAGE_NAME:$IMAGE_TAG" .

Explanation:
Builds a Docker image from the current directory and assigns the image name and tag from CI/CD variables.

Options:
- -t = --tag: Assigns the image name and tag using "$IMAGE_NAME:$IMAGE_TAG".
- . = current directory build context: Sends the current directory as the Docker build context.
------------------------------------------------------------
# echo "$REGISTRY_PASSWORD" | docker login 192.168.94.90:8085 -u "$REGISTRY_USER" --password-stdin

Explanation:
Passes the registry password through standard input and logs in to the private Docker registry with the specified user.

Options:
- | = pipe operator: Sends the output of echo to the standard input of docker login.
- -u = --username: Uses "$REGISTRY_USER" as the registry username.
- --password-stdin = password from standard input: Reads the registry password from standard input instead of the command line.
- 192.168.94.90:8085 = registry address: Connects to the Docker registry on host 192.168.94.90 and port 8085.
------------------------------------------------------------
# docker push "$IMAGE_NAME:$IMAGE_TAG"

Explanation:
Pushes the image identified by "$IMAGE_NAME:$IMAGE_TAG" to the registry encoded in the image name.
------------------------------------------------------------
# docker logout 192.168.94.90:8085

Explanation:
Removes the stored Docker login credentials for the registry at 192.168.94.90:8085.
------------------------------------------------------------

# ls -la

Explanation:
Lists directory contents in long format and includes hidden entries.

Options:
- -l = --format=long: Uses the long listing format with details such as permissions, owner, size, and time.
- -a = --all: Includes entries whose names begin with a dot.
------------------------------------------------------------
# find . -maxdepth 2 -name Dockerfile

Explanation:
Searches from the current directory for files named Dockerfile, descending at most two directory levels.

Options:
- . = current directory search path: Starts the search from the current directory.
- -maxdepth 2 = maximum search depth: Limits traversal to at most two levels below the starting point.
- -name Dockerfile = name test: Matches entries whose base name is exactly Dockerfile.

# docker build -f app/Dockerfile -t myapp .

Explanation:
Builds the image using app/Dockerfile while keeping the current directory as the build context, then tags the result as myapp.

Options:
- -f = --file: Uses app/Dockerfile instead of the default ./Dockerfile.
- -t = --tag: Assigns the image name myapp.
- . = current directory build context: Uses the current directory as the build context.

# /bin/sh -c pip install -r requirements.txt

Explanation:
Runs a command string through /bin/sh; the command installs the Python packages listed in requirements.txt.

Options:
- -c = command string: Tells /bin/sh to read and execute the following command string.
- -r = --requirement: Tells pip to install packages from requirements.txt.
------------------------------------------------------------

Options:
- -r = --requirement: Installs packages from the requirements file requirements.txt.

# sudo usermod -aG docker gitlab-runner

Explanation:

Options:
- -a = --append: Appends the user to the supplementary group list instead of replacing existing supplementary groups.
- -G = --groups: Sets the supplementary group list; here the group value is docker.
