------------------------------------------------------------
# hostname

Explanation:
Prints the hostname of the machine where the GitLab job is running. It is useful for proving that a Shell Executor job is running directly on the runner host.
------------------------------------------------------------
# whoami

Explanation:
Prints the effective username of the current process. In this lesson, it is used to confirm that the job runs as the GitLab Runner service user.
------------------------------------------------------------
# docker --version

Explanation:
Prints the installed Docker client version. This checks whether Docker is available on the Shell Executor host.

Options:
- --version = version information: Prints the Docker version and exits.
------------------------------------------------------------
# python3

Explanation:
Starts the Python 3 interpreter. In this lesson, it illustrates that Python must be installed on the Shell Executor host if a job needs it.
------------------------------------------------------------
# python3 app.py

Explanation:
Runs the Python script named app.py with Python 3. The script is executed using the Python installation available on the runner host.
------------------------------------------------------------
# docker build

Explanation:
Starts a Docker image build command. Without additional arguments, Docker does not have enough information to complete a normal image build.
------------------------------------------------------------
# docker build -t myapp .

Explanation:
Builds a Docker image from the Dockerfile in the current directory and tags it as myapp.

Options:
- -t = --tag (tag): Assigns the name myapp to the built image.
- . = build context: Uses the current directory as the Docker build context.
------------------------------------------------------------
# docker push registry.example.com/myapp

Explanation:
Pushes the image registry.example.com/myapp to the configured container registry. If no explicit tag is present, Docker normally uses the default tag.
------------------------------------------------------------

------------------------------------------------------------
# sudo -u gitlab-runner -H bash -lc 'whoami'

Explanation:
Runs whoami inside a Bash login shell as the gitlab-runner user. This closely simulates the user context used by a Shell Executor job.

Options:
- -u = --user (user): Tells sudo to run the command as gitlab-runner.
- -H = --set-home (set home): Sets HOME to the target user's home directory.
- -l = --login (login shell): Starts Bash as a login shell.
- -c = command string mode: Tells Bash to execute the following command string.
------------------------------------------------------------

# sudo usermod -aG docker gitlab-runner

Explanation:
Adds gitlab-runner to the docker supplementary group without removing its existing supplementary groups.

Options:
- -a = --append (append): Adds the user to the specified supplementary group list instead of replacing the existing list.
- -G = --groups (groups): Specifies the supplementary group list; here the group is docker.

------------------------------------------------------------
# echo "Created by GitLab Shell Executor" > "$TEST_FILE"

Explanation:
Writes the text to the file stored in TEST_FILE. Existing file content is replaced.

Options:
- > = output redirection: Sends standard output to the target file and overwrites existing content.
------------------------------------------------------------
# echo "Pipeline ID = $CI_PIPELINE_ID" >> "$TEST_FILE"

Explanation:
Appends the current GitLab pipeline ID to the file stored in TEST_FILE.

Options:
- >> = append redirection: Sends standard output to the end of the target file without replacing existing content.
------------------------------------------------------------
# echo "Runner Host = $(hostname)" >> "$TEST_FILE"

Explanation:
Runs hostname, inserts its output into the echo text, and appends the result to TEST_FILE.

Options:
- $(hostname) = command substitution: Runs hostname and substitutes its output into the surrounding command.
- >> = append redirection: Appends the command output to the target file.
------------------------------------------------------------
# echo "Runner User = $(whoami)" >> "$TEST_FILE"

Explanation:

Options:
- $(whoami) = command substitution: Runs whoami and substitutes its output into the surrounding command.
- >> = append redirection: Appends the command output to the target file.
