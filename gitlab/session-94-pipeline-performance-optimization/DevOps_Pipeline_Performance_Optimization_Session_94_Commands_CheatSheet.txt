# sudo grep -nE 'concurrent|limit|executor|name' /etc/gitlab-runner/config.toml

Explanation:
Runs grep with elevated privileges and searches the GitLab Runner configuration for the listed settings. It prints matching lines together with their line numbers.

Options:
- -n = --line-number (line number): Prints the input line number before each matching line.
- -E = --extended-regexp (extended regular expression): Interprets the search pattern as an extended regular expression.
- | inside the quoted pattern = regular-expression alternation: Matches concurrent, limit, executor, or name; it is not a shell pipe because it is inside quotes.

# RUN python -m pip install \
    --no-cache-dir \
    --disable-pip-version-check \
    --trusted-host pypi.org \
    --trusted-host files.pythonhosted.org \
    -r requirements.txt

Explanation:
Runs pip through the selected Python interpreter and installs dependencies from requirements.txt during the Docker build. It disables pip caching and version checks and marks the two specified package hosts as trusted.

Options:
- -m = module-name option: Runs the named Python module, here pip; Python does not provide an official long form for this option.
- --no-cache-dir = no cache directory: Disables pip's cache for downloaded packages.
- --disable-pip-version-check = disable pip version check: Prevents pip from checking whether a newer pip version is available.
- --trusted-host pypi.org = trusted host: Treats pypi.org as trusted even when normal TLS trust checks would otherwise block access.
- --trusted-host files.pythonhosted.org = trusted host: Treats files.pythonhosted.org as trusted even when normal TLS trust checks would otherwise block access.
- -r = --requirement (requirement): Installs packages from requirements.txt.
- \\ = shell line continuation: Continues the same RUN command on the next Dockerfile line.

# DOCKER_BUILDKIT=1 docker build -t myapp:test .

Explanation:
Builds a Docker image from the current directory, tags it as myapp:test, and enables BuildKit for this command.

Options:
- DOCKER_BUILDKIT=1 = environment variable assignment: Enables Docker BuildKit for this command invocation.
- -t = --tag (tag): Applies the name and tag myapp:test to the built image.
- . = current-directory build context: Sends the current directory as the Docker build context.
------------------------------------------------------------
# docker build --no-cache -t myapp:test .

Explanation:
Builds the Docker image from the current directory without reusing cached build layers and tags it as myapp:test.

Options:
- --no-cache = no cache: Prevents Docker from using build cache for image layers.
- -t = --tag (tag): Applies the name and tag myapp:test to the built image.
- . = current-directory build context: Sends the current directory as the Docker build context.
