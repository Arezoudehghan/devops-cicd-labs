------------------------------------------------------------
# docker build -t myapp:4f21a6c .

Explanation:
Builds a Docker image from the current directory and names it myapp with the tag 4f21a6c.

Options:
- -t = --tag (tag): Sets the image name and optional tag.
- . = current directory: Uses the current directory as the Docker build context.
------------------------------------------------------------
# docker push IMAGE_NAME

Explanation:
Pushes the specified Docker image to its configured registry. IMAGE_NAME is a placeholder for the full image name.

------------------------------------------------------------
# docker push registry.example.com/devops/myapp:4f21a6c

Explanation:
Pushes the myapp image with tag 4f21a6c to the devops/myapp repository on registry.example.com.

------------------------------------------------------------
# docker build -t registry.example.com/devops/myapp:1.0 .

Explanation:
Builds an image from the current directory and gives it a registry-qualified name with the tag 1.0.

Options:
- -t = --tag (tag): Sets the image name and tag.
- . = current directory: Uses the current directory as the Docker build context.
------------------------------------------------------------
# docker push registry.example.com/devops/myapp:1.0

Explanation:
Pushes the 1.0 tag of myapp to the specified private registry repository.

------------------------------------------------------------
# docker tag myapp:1.0 registry.example.com/devops/myapp:1.0

Explanation:
Creates a new tag for the local myapp:1.0 image using the full registry and repository name.

------------------------------------------------------------
# docker login registry.example.com

Explanation:
Authenticates interactively to registry.example.com. Docker prompts for the required credentials.

------------------------------------------------------------
# docker login registry.example.com -u admin -p MyPassword123

Explanation:
Authenticates to the registry with the username and password provided directly on the command line. This syntax is valid, but putting a password in a command argument is not recommended for CI/CD.

Options:
- -u = --username (username): Specifies the registry username as admin.
- -p = --password (password): Specifies the registry password as MyPassword123.
------------------------------------------------------------
# echo "$REGISTRY_PASSWORD" | docker login "$REGISTRY_URL" \
  --username "$REGISTRY_USER" \
  --password-stdin

Explanation:
Sends the registry password through standard input and logs in without placing the password directly in a Docker command argument. The registry URL and username come from shell variables.

Options:
- | = pipe: Sends the output of echo to the standard input of docker login.
- --username = username: Uses the value of $REGISTRY_USER as the registry username.
- --password-stdin = password from standard input: Reads the password from standard input.
- \ = shell line continuation: Continues the same command on the next line.
------------------------------------------------------------

# mkdir -p "$DOCKER_CONFIG"

Explanation:
Creates the Docker configuration directory for the current job if it does not already exist.

Options:
- -p = --parents (parents): Creates parent directories as needed and does not fail if the directory already exists.
------------------------------------------------------------
# docker image inspect "$IMAGE_TAG"

Explanation:
Displays detailed metadata for the Docker image identified by $IMAGE_TAG and returns a non-zero exit status if the image cannot be inspected.

------------------------------------------------------------
# docker image inspect "$IMAGE_TAG" > /dev/null

Explanation:
Checks whether the image identified by $IMAGE_TAG can be inspected and discards the normal command output.

Options:
- > = output redirection: Redirects standard output to the specified file.
- /dev/null = null device: Discards the redirected output.
------------------------------------------------------------

Options:

# curl -vk https://registry.example.com/v2/

Explanation:
Sends an HTTPS request to the registry API endpoint with verbose output while allowing an untrusted TLS certificate.

Options:
- -v = --verbose (verbose): Shows detailed request, response, and connection information.
- -k = --insecure (insecure): Allows TLS connections without verifying the server certificate.

# docker build --build-arg HTTP_PROXY="$HTTP_PROXY" --build-arg HTTPS_PROXY="$HTTPS_PROXY" --build-arg NO_PROXY="$NO_PROXY" -t "$IMAGE_TAG" .

Explanation:
Builds the Docker image while passing the proxy-related variables as Docker build arguments and tags the result with $IMAGE_TAG.

Options:
- --build-arg = build argument: Passes a build-time variable to the Docker build.
- HTTP_PROXY="$HTTP_PROXY" = build argument value: Passes the HTTP proxy value.
- HTTPS_PROXY="$HTTPS_PROXY" = build argument value: Passes the HTTPS proxy value.
- NO_PROXY="$NO_PROXY" = build argument value: Passes the no-proxy value.
- -t = --tag (tag): Sets the image name and tag.
- . = current directory: Uses the current directory as the Docker build context.
